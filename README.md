# 暗兽棋

一个基于 Vue 3、TypeScript 和 Vite 实现的暗兽棋小游戏。项目支持本地双人、人机对战，以及通过 WebSocket 服务端进行局域网联机。

## 功能特性

- 本地双人对战
- 人机对战，支持简单、中等、困难三档难度
- 局域网双人联机
- 开局翻牌决定双方阵营
- 可选吃鼠规则：
  - 只有猫能吃鼠
  - 除象以外的棋子都能吃鼠
- 4 × 4 交叉点棋盘，共 16 枚棋子
- 豹可以沿八个方向移动，其余棋子只能上下左右移动
- 同等级棋子相撞时双方同时移除
- 鼠可以吃象，但象不能吃鼠
- 中央独立公共大本营
- 大本营内的棋子不受外部敌棋攻击
- 支持进入、离开和从大本营移动
- 大本营有棋子时，豹不能进入，也不能沿穿过中央的对角线移动
- 本地模式支持悔棋、重开和返回菜单
- 联机模式支持发起和处理悔棋请求
- 使用经典动物图片显示棋子，豹使用 Emoji 显示
- 支持桌面端和移动端布局

## 技术栈

- Vue 3
- TypeScript
- Vite
- WebSocket（`ws`）
- `vue-tsc`
- pnpm

规则引擎位于 `src/game/rules.ts`，不依赖 Vue、DOM 或浏览器 API，负责棋盘、棋子、动作合法性、吃子、悔棋和胜负判断。AI 逻辑位于 `src/game/ai.ts`，联机协议定义位于 `src/network/protocol.ts`。

## 环境要求

- Node.js 18 或更高版本
- pnpm 9 或更高版本

## 安装

```powershell
pnpm install
```

如果 pnpm 提示 `esbuild` 的构建脚本被忽略，可以执行：

```powershell
pnpm approve-builds
```

在交互列表中选择 `esbuild` 并确认，然后重新执行安装或构建命令。

## 启动本地游戏

启动 Vite 开发服务器：

```powershell
pnpm dev
```

浏览器打开终端输出的地址，默认通常为：

```text
http://localhost:5173/
```

开发服务器默认监听 `0.0.0.0`，因此也可以通过本机局域网 IP 访问前端页面。

## 启动局域网联机

局域网联机需要同时启动 WebSocket 服务端和前端开发服务器。

1. 启动 WebSocket 服务端：

```powershell
pnpm server
```

服务端监听：

```text
ws://0.0.0.0:3000
```

2. 在另一个终端启动前端：

```powershell
pnpm dev
```

3. 让两台设备访问运行前端的电脑的局域网 IP，例如：

```text
http://192.168.1.100:5173/
```

4. 在游戏菜单选择“局域网联机”：
   - 一台设备点击“创建房间”
   - 另一台设备输入 6 位房间号并点击“加入房间”
   - 房主等待第二位玩家加入后点击“开始对局”

联机客户端会连接当前页面所在主机的 `3000` 端口。请确保两台设备处于同一局域网，并允许防火墙放行 TCP `3000` 端口和前端开发服务器端口。

启动服务端的开发模式也可以使用：

```powershell
pnpm server:dev
```

## 游戏规则

### 棋盘和棋子

棋盘包含 4 × 4 个交叉点，共 16 枚棋子。红蓝双方各拥有一套：

```text
象、狮、虎、豹、狼、狗、猫、鼠
```

开局时所有棋子背面朝上。首位翻开棋子的玩家获得该棋子的阵营，对手自动获得另一阵营。

### 棋子等级

棋子等级由高到低为：

```text
象 > 狮 > 虎 > 豹 > 狼 > 狗 > 猫 > 鼠
```

通常情况下，高等级棋子可以吃低等级棋子。同等级棋子相撞时，双方同时移除。

特殊规则：

- 鼠可以吃象
- 象不能吃鼠
- 启用“只有猫能吃鼠”时，只有猫可以吃鼠
- 未翻开的棋子不能移动或被主动攻击

### 移动

- 普通棋子每次上下左右移动一格
- 豹每次可以上下左右或沿对角线移动一格
- 棋子可以从营位入口进入空的大本营
- 大本营最多容纳一枚棋子
- 大本营内的棋子可以移动到四个营位入口
- 大本营内的棋子不会被外部棋子直接攻击
- 大本营有棋子时，豹不能进入大本营
- 大本营有棋子时，豹不能沿穿过中央大本营的对角线移动

### 胜负

当一方所有棋子都被移除，或该方没有任何合法动作时，另一方获胜。

## AI 说明

AI 会根据当前局面的合法动作进行评分：

- 阵营未确定时随机翻牌
- 吃子动作优先考虑目标棋子价值
- 鼠吃象会获得额外评分
- 会评估移动后受到相邻敌棋攻击的风险
- 会考虑接近已翻开敌方棋子的收益
- 低收益局面会保留一定随机翻牌行为

AI 难度对应不同搜索配置入口，目前前端提供简单、中等、困难三个选项。

## 联机架构

联机模式采用客户端、WebSocket 服务端和共享规则引擎的结构：

```text
Vue 客户端
  │ 发送翻牌、移动、悔棋等操作
  ▼
WebSocket 服务端
  │ 校验玩家身份和动作合法性
  ▼
规则引擎
  │ 更新房间状态并广播
  ▼
所有联机客户端
```

服务端使用 `src/game/rules.ts` 校验收到的动作，客户端不能直接决定联机棋局状态。房间状态保存在服务端内存中，服务端重启后房间和对局会被清除。

## 构建生产版本

```powershell
pnpm build
```

构建产物输出到 `dist/` 目录。当前项目的 WebSocket 服务端仍需单独启动，生产环境部署时需要将前端静态资源和 `server/index.ts` 分开部署，并根据实际域名、端口和代理配置调整联机连接地址。

构建后的前端目录按用途分组：

```text
dist/
├─ index.html
└─ assets/
   ├─ js/                 # JavaScript bundle
   ├─ css/                # CSS bundle
   └─ images/             # 图片、图标和 favicon
      ├─ animal/
      ├─ home/
      ├─ index/
      └─ pieces/
```
